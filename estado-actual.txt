#### 2026-07-23 — Diagnóstico: texto genérico en imágenes (LLM → stub)

| Hallazgo | Detalle |
|----------|---------|
| **Síntoma** | El texto de overlay en las imágenes salía genérico (plantillas), no ideado a partir de los parámetros del brief |
| **Causa raíz** | Los agentes caían al `_stub()` determinista. `get_llm()` (`llm.py:98`) devuelve un `OllamaLLM` **aunque Ollama esté apagado**; cada llamada lanza excepción → `strategist`/`copywriter` la atrapan → stub → texto de plantilla |
| **Capa 2 (cold-start)** | Aun con Ollama encendido, la **primera** llamada carga el modelo (~4.9 GB) y supera el timeout httpx de 180s (`llm.py:35`) → `strategist.llm_error='timed out'` → stub. El `mensaje_base` genérico del stub se propaga al subline de la imagen |
| **Verificación** | Con el modelo **caliente**, el estratega responde en ~21s y genera texto específico y creativo usando los parámetros del brief (público, tono, objetivo). Config `.env` correcta (`OLLAMA_MODEL=llama3.1`) — no había mismatch de modelo |
| **Agravante** | Ollama descarga el modelo tras ~5 min inactivo → el cold-start (y el timeout) **reaparece** en la primera generación tras inactividad o reinicio |
| **Mitigación operativa** | Mantener `ollama serve` corriendo y el modelo pre-cargado/caliente antes de generar. Requisito real, no opcional: sin LLM vivo y caliente, el copy sale genérico sin error visible al usuario |
| **Fix de código propuesto (no aplicado)** | En `llm.py`: agregar `keep_alive` al payload de Ollama (evita descarga entre llamadas/runs) + subir el timeout de cold-start (~300s). Pendiente de decisión |

### Qué es el proyecto

MVP de automatización de marketing con agentes de IA:

```
brief → estrategia → copy con QA → diseño (imagen o reel) → aprobación humana → publicación en redes
```

Flujo principal de publicación: **Meta / Instagram Business** y **LinkedIn** vía sidecar Go (OAuth nativo).

### Video as Code — Reels programáticos (Fase D)

**Trigger:** el mismo campo `content_format` que ya existía (`"feed"` / `"story"`) ahora acepta `"reel"`. No hay campo nuevo, no hay migración de `AgentRun`.

**Pipeline (rama paralela a imagen, mismo brief→estrategia→copy/QA):**

```
Strategist → Copywriter/QA → VideoScriptAgent (guion 3-5 escenas)
        → VideoDesignerAgent:
              escenas: fal.ai still (1080×1920) + Ken Burns
              voz: fal.ai Kokoro Spanish (principal en dev) / ElevenLabs / OpenAI TTS (banda 15-30s)
              → Timeline (JSON provider-neutral) → render_video() (Shotstack block-and-poll)
                 · overlays = clips TitleAsset (pista superior); media abajo
                 · src localhost → PUBLIC_IMAGE_BASE_URL antes del submit
        → HITL (pending_approval, igual que imagen)
        → Go sidecar (media_type=REELS, video_url) → Meta Graph API
```

**Módulos en** `agents/marketing_agents/`:

| Archivo | Rol |
|---------|-----|
| `video_script.py` | `VideoScriptAgent` — guion 3-5 escenas + hook + CTA, banda 15-30s por conteo de palabras |
| `video_timeline.py` | Contrato Pydantic `Timeline`/`Scene`/`VoiceoverTrack` + `to_shotstack_edit()` (pistas captions→títulos→media; sin `title_asset`) |
| `voice_providers.py` | `synthesize_voice()` — fal TTS (principal en `.env` de dev) / ElevenLabs / OpenAI / mock; español por defecto |
| `video_providers.py` | `render_video()` — Shotstack (publicize URLs → submit → poll → descarga MP4) / mock; body de error HTTP en logs |
| `video_designer.py` | `VideoDesignerAgent` — orquesta escenas + voz + timeline + render, devuelve `VideoDesignOutput` |

**Dimensiones:** 1080×1920 (9:16), 30 fps, MP4 — mismo spec 9:16 que stories (`resolve_image_spec` acepta `"reel"`).

**Async-only:** `content_format="reel"` se rechaza con `422` en `POST /runs/sync`; solo corre vía `POST /runs/async`, en una cola Celery dedicada `video_render` (renders tardan minutos, no deben competir con la cola de imágenes). Requiere levantar un **segundo worker**:

```bash
python -m celery -A workers.celery_app.celery_app worker -l info -Q video_render
```

La tarea (`execute_video_pipeline_task`) usa el `celery.Task` base plano — **sin** `autoretry_for` — para no re-renderizar video ante fallos transitorios (costo + duplicados). Timeout ~20 min vía `task_annotations` en `celery_app.py`.

**Persistencia:** `GeneratedAsset.video_url` (columna nullable, migración Alembic `0005`); `result["design"]` sigue siendo la misma clave para imagen y reel (`video_url` seteado + `image_url` `None` en reels).

| `transcription_providers.py` | `transcribe_clips()` — Whisper (`whisper-1`, timestamps por palabra) vía `subprocess`(ffmpeg) + chunking >25MB con offset-correction; `mock` para tests |
| `clip_assets.py` | `clip_public_url()` — mapea path local de clip descargado a URL servida (mismo patrón que `user_assets.py`) |
| `clip_editor.py` | `ClipEditorAgent` — LLM (JSON de segmentos) con fallback determinístico a stub; heurísticas de hook (brevedad, pregunta/número/revelación, ritmo); banda de duración total 6-60s (`_MIN_CLIP_S`/`_MAX_CLIP_S`), nunca la banda 15-30s de `reel` |
| `clip_reel_designer.py` | `ClipReelDesigner` — orquesta drive → transcripción → selección → efecto opcional → `Timeline` → render; **importante:** si el efecto wan reemplaza el video del segmento hook, `trim_in`/`trim_out` se resetean a `0`/`duration_s` (el output del efecto YA es el segmento recortado, no el clip fuente completo) |

**`video_timeline.py` extendido:** `Scene.asset_type: Literal["image","video"]="image"`, `Scene.trim_in`/`trim_out` (solo aplica a `"video"`), nueva clase `Caption` y `Timeline.captions` (pista overlay de títulos en `to_shotstack_edit`, encima de media); la validación de narración (`headline`/`subline` obligatorios) ahora solo exige texto en escenas `"image"` — las de `"video"` no la requieren. Los textos de overlay son clips `asset.type=title` (estilo Shotstack `minimal`/`subtitle`), no una propiedad `title_asset`.

**Variables `.env` nuevas (ver `.env.example`):**

```env
STT_PROVIDER=whisper
EFFECTS_ENABLED=false
FAL_EFFECTS_MODEL=fal-ai/wan-effects
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GOOGLE_REDIRECT_URI=http://localhost:8000/api/auth/callback/google
```

**Dependencia de sistema NUEVA:** `ffmpeg` debe estar instalado y en el `PATH` (usado vía `subprocess` para extraer audio antes de transcribir). No es necesario para `feed`/`story`/`reel` generado.

**URLs públicas:** `video_providers._publicize_edit` reescribe `localhost` → `PUBLIC_IMAGE_BASE_URL` en el JSON enviado a Shotstack (clips + soundtrack). `clip_assets.py` sigue generando URLs locales; si `EFFECTS_ENABLED=true`, fal.ai wan-effects aún necesita ngrok activo a mitad de pipeline. La publicación Meta también normaliza en `_publish_via_go`.

**Google OAuth:** el scope `drive.readonly` puede requerir verificación manual de la app por parte de Google para usuarios externos a tu organización (proceso de días/semanas). En dev, agregar el email como "test user" en la pantalla de consentimiento OAuth (modo "Testing") evita el trámite.

**Captions:** se generan **por segmento** (un cue de subtítulo por segmento seleccionado), no por palabra — granularidad más fina queda para v2.

### Publicación en redes (estable)

#### Instagram / Meta

- OAuth Meta con fallback granular de scopes
- Estado `publishing` para evitar doble publicación
- Go publisher en `:8088`
- `PUBLIC_IMAGE_BASE_URL` con ngrok obligatorio para que Meta acceda a las imágenes
- Anti-duplicados por error 9007 (container no `FINISHED`)
- **Reels** (`content_format="reel"`): rama `media_type=REELS` + `video_url` en `PublishMeta`; timeout de contenedor ampliado a 300s (vs 60s en imagen/story) porque Meta procesa video mucho más lento

#### LinkedIn (nativo)

- OAuth: `/api/auth/login/linkedin` → callback → tokens en `oauth_tokens`
- Scopes: `openid profile w_member_social`; URN vía `/v2/userinfo`
- Publicación con imagen: `registerUpload` → PUT binario → `ugcPosts`
- Sidecar Go (`internal/publisher/linkedin.go`) + fallback Python en `social_providers.py`

### Resumen

MVP **end-to-end funcional**: genera copy con QA bajo doctrina inbound (Entretener→Informacion→Conexion; comunidad del brief), produce imágenes editoriales con fal.ai/Flux (o usa la foto del usuario como capa base sin destruirla), aplica layouts tipo agencia con Pillow, permite alteración img2img bajo indicaciones del usuario con aprobación humana, publica en Instagram y LinkedIn vía Go + OAuth nativo **multi-cuenta** (selector de cuenta destino por run; requiere token Meta con permisos IG), genera Reels programáticos (guion → escenas fal.ai + voz fal → render Shotstack; assets fal vía CDN `fal.media`), y arma Reels a partir de clips propios del usuario (Drive → Whisper → selección → captions → efecto opcional → mismo render/publicación). HITL con Aprobar/Rechazar y **Solicitar cambios**, que regenera la pieza con las notas del revisor vía `POST /runs/{id}/revise` y la devuelve a `pending_approval`. TikTok queda como fase 2 (Login Kit + Content Posting; auditoría de app).
