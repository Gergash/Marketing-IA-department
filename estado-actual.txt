### Qué es el proyecto

MVP de automatización de marketing con agentes de IA:

```
brief → estrategia → copy con QA → diseño (imagen o reel) → aprobación humana → publicación en redes
```

Flujo principal de publicación: **Meta / Instagram Business** y **LinkedIn** vía sidecar Go (OAuth nativo).

### Motor visual — fal.ai + diseño editorial (Fase B)

**Proveedor recomendado:** `IMAGE_PROVIDER=fal` con `FAL_API_KEY` y `FAL_MODEL=fal-ai/flux-pro/v1.1`

Flujo en diseño **sin foto de usuario**:

1. `pick_archetype(brief, strategy)` elige layout (o `archetype_override` vía API)
2. `build_flux_prompt()` genera prompt visual sin texto embebido
3. fal.ai genera fondo con dimensiones por plataforma/formato
4. `apply_design_layout()` aplica composición editorial con Pillow

**4 arquetipos:**

| ID | Label | Cuándo se elige |
|----|-------|-----------------|
| `typographic_poster` | Poster tipográfico | promocional / ventas |
| `minimal_conceptual` | Conceptual minimal | informativo |
| `editorial_infographic` | Infográfico editorial | educativo / branding |
| `cinematic_hero` | Hero cinematográfico | storytelling / entretenimiento |

**Dimensiones** (`image_specs.py`):

- Instagram / Facebook feed: **1080×1350 (4:5)**
- Story / reels: **1080×1920 (9:16)**
- LinkedIn feed: 1200×627
- X/Twitter feed: 1200×675
- fal escala proporcionalmente si alguna dimensión > 1440px (stories → ~810×1440)

**Frontend:** selector feed/story/reel, switch fal ↔ Stable Diffusion, dropdown de arquetipo, upload de foto, toggle img2img, muestra `layout_label`, `design_source` y preview de video en reels.

ComfyUI descartado (GPU 4 GB insuficiente). Stable Diffusion local conservado como alternativa.

### Foto del usuario — Design-as-Code + img2img gobernado (Fase C)

Dos modos al subir una imagen desde el dashboard:

| Modo | Toggle | Comportamiento | `design_source` |
|------|--------|----------------|-------------------|
| **No destructivo** | OFF | Foto intacta como capa base → fit al formato → overlay Pillow | `user_overlay` |
| **Alteración IA** | ON + prompt | fal img2img (`FAL_IMG2IMG_MODEL`) → overlay Pillow → `pending_approval` | `user_img2img` |
| **Sin foto** | — | Flujo clásico txt2img fal/SD | `generated` |

**Flujo técnico:**

1. `POST /api/briefs/upload-asset` → guarda JPEG/PNG/WebP (máx. 10 MB) en `static/uploads/`

3. `DesignerAgent` bifurca: `compose_from_user_asset()` vs `generate_image()`
4. Resultado final en `static/images/` (`user_overlay_*` o `user_img2img_*`)

**Variables img2img:**


### Video as Code — Reels programáticos (Fase D)

**Trigger:** el mismo campo `content_format` que ya existía (`"feed"` / `"story"`) ahora acepta `"reel"`. No hay campo nuevo, no hay migración de `AgentRun`.

**Pipeline (rama paralela a imagen, mismo brief→estrategia→copy/QA):**

```
Strategist → Copywriter/QA → VideoScriptAgent (guion 3-5 escenas)
        → VideoDesignerAgent:
              escenas: fal.ai still (1080×1920) + Ken Burns
              voz: ElevenLabs/OpenAI TTS (español, banda 15-30s)
              → Timeline (JSON provider-neutral) → render_video() (Shotstack block-and-poll)
        → HITL (pending_approval, igual que imagen)
        → Go sidecar (media_type=REELS, video_url) → Meta Graph API
```

**Módulos nuevos en** `agents/marketing_agents/`:

| Archivo | Rol |
|---------|-----|
| `video_script.py` | `VideoScriptAgent` — guion 3-5 escenas + hook + CTA, banda 15-30s por conteo de palabras |
| `video_timeline.py` | Contrato Pydantic `Timeline`/`Scene`/`VoiceoverTrack` + `to_shotstack_edit()` (único lugar donde se filtra el JSON de Shotstack) |
| `voice_providers.py` | `synthesize_voice()` — ElevenLabs (principal) / OpenAI TTS (alt) / mock; español por defecto |
| `video_providers.py` | `render_video()` — Shotstack (submit → poll → descarga MP4) / JSON2Video (documentado, no implementado) / mock |
| `video_designer.py` | `VideoDesignerAgent` — orquesta escenas + voz + timeline + render, devuelve `VideoDesignOutput` |

**Dimensiones:** 1080×1920 (9:16), 30 fps, MP4 — mismo spec 9:16 que stories (`resolve_image_spec` acepta `"reel"`).

**Async-only:** `content_format="reel"` se rechaza con `422` en `POST /runs/sync`; solo corre vía `POST /runs/async`, en una cola Celery dedicada `video_render` (renders tardan minutos, no deben competir con la cola de imágenes). Requiere levantar un **segundo worker**:

La tarea (`execute_video_pipeline_task`) usa el `celery.Task` base plano — **sin** `autoretry_for` — para no re-renderizar video ante fallos transitorios (costo + duplicados).

**Persistencia:** `GeneratedAsset.video_url` (columna nullable, migración Alembic `0005`); `result["design"]` sigue siendo la misma clave para imagen y reel (`video_url` seteado + `image_url` `None` en reels).

### Reel con clips del usuario (Fase E)

**Trigger:** nuevo valor de `content_format`: `"user_clip_reel"` (async-only, igual que `"reel"`). Requiere `drive_folder_id` en el request (422 si falta o si se usa `/runs/sync`).

**Pipeline (rama hermana de `reel`, mismo brief→estrategia→copy/QA):**

```
Strategist → Copywriter/QA → ClipReelDesigner:
    drive_source.list_and_download_clips(drive_folder_id)  [OAuth Google, drive.readonly]
        → transcription_providers.transcribe_clips()        [ffmpeg extrae audio → Whisper word-ts]
        → ClipEditorAgent.run()                              [selección hook-scored, banda 6-60s]
        → [fal.ai wan-effects opcional sobre el segmento hook, EFFECTS_ENABLED]
        → Timeline (Scene asset_type="video" + captions) → render_video() (Shotstack)
    → HITL (pending_approval, igual que imagen/reel)
    → Go sidecar (media_type=REELS, mismo branch que "reel") → Meta Graph API
```

**Módulos nuevos en** `agents/marketing_agents/`:

| Archivo | Rol |
|---------|-----|
| `drive_source.py` | OAuth Google Drive (`auth_social.py` provider `"google"`) — listar/descargar clips de una carpeta; filename sanitizado (`Path(...).name`) + prefijado por id (evita path traversal y sobrescritura por duplicados) |
| `transcription_providers.py` | `transcribe_clips()` — Whisper (`whisper-1`, timestamps por palabra) vía `subprocess`(ffmpeg) + chunking >25MB con offset-correction; `mock` para tests |
| `clip_assets.py` | `clip_public_url()` — mapea path local de clip descargado a URL servida (mismo patrón que `user_assets.py`) |
| `clip_editor.py` | `ClipEditorAgent` — LLM (JSON de segmentos) con fallback determinístico a stub; heurísticas de hook (brevedad, pregunta/número/revelación, ritmo); banda de duración total 6-60s (`_MIN_CLIP_S`/`_MAX_CLIP_S`), nunca la banda 15-30s de `reel` |
| `clip_reel_designer.py` | `ClipReelDesigner` — orquesta drive → transcripción → selección → efecto opcional → `Timeline` → render; **importante:** si el efecto wan reemplaza el video del segmento hook, `trim_in`/`trim_out` se resetean a `0`/`duration_s` (el output del efecto YA es el segmento recortado, no el clip fuente completo) |

**`video_timeline.py` extendido:** `Scene.asset_type: Literal["image","video"]="image"`, `Scene.trim_in`/`trim_out` (solo aplica a `"video"`), nueva clase `Caption` y `Timeline.captions` (2ª pista de título en `to_shotstack_edit`); la validación de narración (`headline`/`subline` obligatorios) ahora solo exige texto en escenas `"image"` — las de `"video"` no la requieren.

**Variables `.env` nuevas (ver `.env.example`):**

```env
STT_PROVIDER=whisper
EFFECTS_ENABLED=false
FAL_EFFECTS_MODEL=fal-ai/wan-effects
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GOOGLE_REDIRECT_URI=http://localhost:8000/api/auth/callback/google
```

**Dependencia de sistema NUEVA:** `ffmpeg` debe estar instalado y en el `PATH` (usado vía `subprocess` para extraer audio antes de transcribir). No es necesario para `feed`/`story`/`reel` generado.

**Limitación conocida:** las URLs de clips y del video final (`clip_assets.py`, `video_providers.py`) se generan siempre como `http://localhost:8000/static/...`; la sustitución a `PUBLIC_IMAGE_BASE_URL` (necesaria para que servicios externos como fal.ai/Shotstack alcancen el archivo) solo ocurre en el paso final de publicación (`_publish_via_go`), no a mitad de pipeline. Si el efecto wan o Shotstack necesitan bajar el clip desde fuera de la máquina, ngrok + `PUBLIC_IMAGE_BASE_URL` deben estar activos durante la ejecución del run, no solo al publicar.

**Google OAuth:** el scope `drive.readonly` puede requerir verificación manual de la app por parte de Google para usuarios externos a tu organización (proceso de días/semanas). En dev, agregar el email como "test user" en la pantalla de consentimiento OAuth (modo "Testing") evita el trámite.

**Captions:** se generan **por segmento** (un cue de subtítulo por segmento seleccionado), no por palabra — granularidad más fina queda para v2.

### Publicación en redes (estable)

#### Instagram / Meta

- OAuth Meta con fallback granular de scopes
- Estado `publishing` para evitar doble publicación
- Go publisher en `:8088`
- `PUBLIC_IMAGE_BASE_URL` con ngrok obligatorio para que Meta acceda a las imágenes
- Anti-duplicados por error 9007 (container no `FINISHED`)
- **Reels** (`content_format="reel"`): rama `media_type=REELS` + `video_url` en `PublishMeta`; timeout de contenedor ampliado a 300s (vs 60s en imagen/story) porque Meta procesa video mucho más lento

#### LinkedIn (nativo)

- OAuth: `/api/auth/login/linkedin` → callback → tokens en `oauth_tokens`
- Scopes: `openid profile w_member_social`; URN vía `/v2/userinfo`
- Publicación con imagen: `registerUpload` → PUT binario → `ugcPosts`
- Sidecar Go (`internal/publisher/linkedin.go`) + fallback Python en `social_providers.py`

### Cómo levantar el stack (7–8 terminales)

Documentación detallada: **`infra/arranque-stack.md`**

**Prerequisitos (una vez):**

```bash
pip install -r requirements.txt
python -m alembic upgrade head   # incluye migración 0005 (video_url)
cd frontend && npm install && cd ..
```

**Servicios (terminales separadas — raíz del repo, venv activado):**

```bash
# T1 — Infra
docker compose -f infra/docker-compose.yml up -d

# T2 — Ollama
curl http://localhost:11434/api/tags

# T3 — API
python -m uvicorn gateway.app.main:app --reload --host 127.0.0.1 --port 8000

# T4 — Celery (runs async imagen/story)
python -m celery -A workers.celery_app.celery_app worker -l info

# T4b — Celery video_render (solo si generas Reels)
python -m celery -A workers.celery_app.celery_app worker -l info -Q video_render

# T5 — Frontend
cd frontend && npm run dev

# T6 — Go publisher (al aprobar/publicar en IG, LinkedIn o Reels)
cd microservices/social-publisher-go && go run ./cmd/server

# T7 — ngrok (solo al publicar en Meta/Instagram — imágenes y videos)
cd tests/ngrok-v3-stable-windows-amd64 && ./ngrok.exe http 8000
# Actualizar PUBLIC_IMAGE_BASE_URL con la URL https y reiniciar Uvicorn
```

### Resumen

MVP **end-to-end funcional**: genera copy con QA, produce imágenes editoriales con fal.ai/Flux (o usa la foto del usuario como capa base sin destruirla), aplica layouts tipo agencia con Pillow, permite alteración img2img bajo indicaciones del usuario con aprobación humana, publica en Instagram y LinkedIn vía Go + OAuth nativo, genera Reels programáticos (guion → escenas fal.ai + voz ElevenLabs → render Shotstack), y arma Reels a partir de clips propios del usuario (Drive OAuth → transcripción Whisper → selección hook-scored → captions → efecto visual opcional → mismo render/publicación que Reels), todo publicado de forma async con aprobación humana idéntica al flujo de imagen.
