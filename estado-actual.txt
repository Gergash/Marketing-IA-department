#### 2026-09-29 — Agentes escriben copy con LLM real (OpenRouter gratis)

| Entrega | Detalle |
|---------|---------|
| **Diagnóstico** | Prod tenía `LLM_PROVIDER=ollama` → `localhost:11434` desde agosto; no hay Ollama en los contenedores → `ConnectError` → strategist/copywriter caían a `creative_copy_fallback` (plantilla con el tema pegado literal) sin error visible. Afectaba a todos los departamentos, con o sin redes conectadas |
| **OpenRouter** | La cuenta no tiene créditos (modelos de pago → **402**); `google/gemini-2.0-flash-001` ya no existe (**404**). Se usan modelos `:free` |
| **`OpenAILLM._create`** | Reintentos (2s/5s/10s) ante 429, 5xx y respuestas 200 **sin `choices`** (saturación de los `:free`) |
| **Fallbacks** | `OPENAI_MODEL_FALLBACKS` → `extra_body.models` (OpenRouter acepta **máx. 3** modelos en total) |
| **Sin razonamiento** | `OPENROUTER_DISABLE_REASONING=true` → `reasoning.enabled=false`: los razonadores gratis agotaban `max_tokens` pensando y devolvían `content` vacío |
| **JSON tolerante** | `_parse_json` extrae el objeto aunque venga con fences o texto alrededor |
| **Validación** | Probado dentro del worker de prod: copy real en 8–14s por pieza. `.env.production` ya configurado (backup `.env.production.bak.*-llm`) |
| **Límites** | Free tier: tope diario de peticiones sin créditos; el modelo puede inventar horarios/detalles no dados en el brief |
| **Commit** | `49cbd0f` en `main`; falta merge a `master` + `up -d --build api worker video-worker` |

### Motor visual y marca

**Proveedores de imagen:** `IMAGE_PROVIDER=openai_image|fal|venice|stable_diffusion|openai|mock`. El switch de la UI (`GET /api/image/providers`) solo ofrece **`openai_image`** (gpt-image-2 directo, default) y **`fal`** cuando tienen key; Venice queda reservado para video. `openai` = DALL·E 3 legacy, no confundir con `openai_image`.

**5 arquetipos** (`layout_archetypes.py`):

| ID | Cuándo |
|----|--------|
| `brand_campaign_piece` | Manual de marca activo (logo + foto full-bleed + tipografía centrada) — ver `docs/references/` |
| `typographic_poster` | Promocional / ventas |
| `minimal_conceptual` | Informativo |
| `editorial_infographic` | Educativo / branding (sin manual) |
| `cinematic_hero` | Storytelling / entretenimiento |

**Flujo brand book:**

1. Subir PDF → pypdf; si texto corto y `OCR_PROVIDER=paddle` → PaddleOCR  
2. `scan_brand_pdf` → paleta + logos PNG en `static/uploads/brand/{tenant}/`  
3. Brief carga `brand_context` + `brand_palette` + `brand_logo_paths`  
4. Designer fuerza campaña de marca, colores del scan, fonts OFL/Windows, pega logo  

**Stories:** overlay Pillow centrado. **CTA en imagen:** solo con `cta_on_image=true` (salvo pieza de campaña con marca). Hashtags/`link_url` van al caption. **Contraste:** `text_contrast.py` mide la luminancia de la zona del texto y elige color/viñeta.

### Formatos de publicación por red

Fuente única: `image_specs.py` (`_NETWORK_FORMATS` + `_SPECS`), expuesta por `GET /api/image/formats`.

| Red | Formatos | Feed |
|-----|----------|------|
| Instagram / Facebook | feed, story, reel, user_clip_reel, universal | 1080×1350 |
| LinkedIn | feed, universal | 1200×627 |
| TikTok | story, reel, user_clip_reel, universal | — (solo vertical 1080×1920) |
| X (Twitter) | feed, reel, universal | 1200×675 |

**`universal` = 1080×1080** idéntico en todas las redes: el encuadre que ninguna recorta agresivamente, para cuando la misma pieza va a varias redes. En layout y publicación se comporta como `feed`.

**X:** publicación nativa OAuth 1.0a (`social_providers.py`): tweet + imagen. Conectar vía Integraciones **o** `X_ACCESS_TOKEN` + `X_ACCESS_TOKEN_SECRET` en `.env`. Portal: permisos **Read and write**, tipo **Web App**, callback prod. **TikTok:** solo generación; app en App Review; OAuth/publish fase 2.

### Capa SaaS (landing + créditos)

Activación **obligatoria en dos sitios**:

| Capa | Variable | Dónde |
