  3. Estado de cada componente

  Pipeline de Agentes — COMPLETO

  Flujo: Strategist → [LangGraph: Copywriter ↔ QA] → Designer → Publisher

  - ContentStrategistAgent (strategist.py): produce tipo_post, hook, mensaje_base, hashtags. Usa LLM configurado o stub determinístico.
  - CopywriterAgent (copywriter.py): genera copy_final, hashtags, cta. Acepta qa_feedback para revisiones.
  - ContentQualityGuard (quality.py): reglas de compliance — palabras bloqueadas (estafa, fake, garantizado 100%) + heurística de tono formal vs exclamaciones.
  - Subgrafo LangGraph (graph_copy_qa.py): bucle Copywriter↔QA con hasta 3 intentos, trazabilidad de eventos (events: list[dict]) y arista condicional finish/revise.
  - DesignerAgent (designer.py): construye prompt visual y llama a generate_image().
  - PublisherAgent (publisher.py): capa fina sobre social_providers.publish_post().

  Scheduler de Campañas — AHORA FUNCIONAL (fix aplicado hoy)

  Antes: solo leía la tabla campaign_schedules cada 5 minutos, sin disparar nada.

  Ahora:
  - start_scheduler() hace sincronización inicial al arrancar la API
  - _sync_campaign_jobs() (cada 5 min): compara campañas activas en BD con jobs en APScheduler — agrega nuevas, actualiza expresiones cron modificadas, elimina las desactivadas  
  - _fire_campaign(): crea un Brief con los datos de la campaña y ejecuta execute_pipeline() con requires_approval=True — el resultado queda en pending_approval para revisión    
  humana antes de publicar
  - Cron expression inválida: se loguea warning y se omite ese job sin romper el scheduler

  # 5. Frontend (terminal separada)
  cd frontend && npm run dev
