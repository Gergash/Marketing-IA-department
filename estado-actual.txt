  3. Problemas y deuda técnica detectados

  CRÍTICO — Python version mismatch

  - .python-version declara 3.10 (correcto para Stable Diffusion)
  - Pero el .venv instalado contiene rutas cpython-313 — el entorno virtual es Python 3.13
  - Consecuencia: los paquetes del venv son 3.13, pero si se ejecuta con el Python 3.10 del proyecto, habrá incompatibilidades. Stable Diffusion A1111 puede fallar con 3.13.     

  MEDIO — Imagen URL no se sustituye en publicación Python directa

  - social_providers.py → _meta_instagram() envía http://localhost:8000/static/images/... a Meta
  - Meta exige una URL HTTPS pública — la imagen nunca cargará en Instagram si se usa el publisher Python directamente (sin Go)
  - La sustitución por PUBLIC_IMAGE_BASE_URL solo ocurre en _publish_via_go() en pipeline_service.py

  MEDIO — LinkedIn Python (sin imagen)

  - El publisher Python de LinkedIn (social_providers.py) solo envía texto (shareMediaCategory: "NONE")
  - El Go publisher sí sube la imagen correctamente (4 pasos: download → initUpload → upload → createPost)
  - Si Go no está corriendo y se usa el fallback Python, los posts de LinkedIn salen sin imagen

  BAJO — Scheduler de campañas es placeholder

  - scheduler_service.py registra un job _heartbeat_job cada 5 minutos
  - Solo hace SELECT de campañas habilitadas, no las ejecuta
  - La tabla campaign_schedules con cron_expr existe pero no hay lógica de disparo real

  BAJO — Alembic: conflicto de nombres de archivo

  - 20260206_0003_agent_runs_content_format.py y 20260511_0003_add_oauth_tokens.py ambos tienen "0003" en el nombre de archivo
  - El último tiene revision = "0004" y down_revision = "0003" (correcto internamente)
  - El nombre de archivo es engañoso pero no rompe nada

  BAJO — CSRF state OAuth en memoria

  - _pending_states: dict[str, str] = {} se pierde al reiniciar el API
  - En dev está bien, pero en prod con múltiples workers o reinicios el callback fallará con "State inválido"

  BAJO — infra/Untitled archivo sin seguimiento

  - Contiene solo el texto docker-compose.platform.yml — parece un residuo accidental

  BAJO — MCP connect-go es un stub

  - publish_social_stub tool solo devuelve un string con platform + image + chars
  - No tiene integración real con social-publisher-go

  BAJO — schema_patches.py no cubre oauth_tokens

  - En SQLite dev, Base.metadata.create_all() crea oauth_tokens si la tabla no existe
  - Pero si alguien tiene un marketing.db antiguo (pre-OAuth), create_all no agrega la tabla nueva
  - Solución: Agregar CREATE TABLE IF NOT EXISTS oauth_tokens a schema_patches.py
